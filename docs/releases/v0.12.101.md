# KiCad Online 0.12.101 / Android 1.99

This preview expands desktop project limits, improves repeat loading, and
corrects native schematic orientation. Store availability is tracked separately
in [Downloads and store availability](../RELEASE-STATUS.md).

## Changes

- Modern desktop KiCad schematic and PCB reads allow up to 256 MiB per source
  and 512 MiB of retained project sources. Parser, comparison and connectivity
  checks use matching limits. Legacy files, reports, metadata and binary assets
  retain separate limits. Android uses a smaller 64 MiB modern-file profile.
  Desktop drawing and net-selection geometry permits up to 1.5 million
  primitives; Android retains a 250,000-primitive profile.
- Large browser-session source replies use caller-scoped, expiring chunks
  instead of attempting to send the complete file in one Chrome message.
  Serialized reply and memory budgets remain enforced; these ceilings are not
  guarantees that every source below them fits every device.
- Oversized source downloads run alone. Waiting for a download slot no longer
  consumes the active-read timeout. Cancellation, failed-read retry, immutable
  revision checks and existing repository access remain intact.
- Repeated local disk reads reuse bounded snapshot data. Returning to the same
  Android drawing preserves its workspace. Search, Inspect, Fit and Tools are
  directly reachable in the simplified mobile toolbar.
- First-use 3D rendering uses Realistic appearance, Studio lighting and Sharp
  quality without ambient occlusion. Saved preferences remain respected.
  Loading a component model updates that component instead of rescanning all
  component visibility.
- **Expand mode** separates saved copper layers, lifts component models and
  stand-ins, stretches vias, and fades the represented substrate. Expanded
  copper uses layer colors. Selection overlays and source-linked focus follow
  the moved geometry during the transition.

- Narrow embedded 3D previews use one compact Fit/View/More row. Secondary
  tools start closed, retain the same handlers, and return inline in a wide
  viewer.

- Schematic fields now follow KiCad parent-relative orientation and justification,
  while preserving saved world anchors. Mirroring applies after symbol rotation;
  legacy schematic conversion retains its world field orientation.

## Validation scope

The JavaScript gate passed 2,845 tests. The Python suite ran 167 tests with no failures
and one Windows symlink-privilege skip. A 400 × 550 px browser harness
verified the compact 3D toolbar, closed/open More menu and usable drawing
viewport on the retained public 3PD+IB board. This is a harness check, not
installed-extension or site-deployment acceptance.

Native KiCad 10.0.6 exports checked 12 asymmetric-symbol placements and 12
actual Connector:TestPoint placements across all orthogonal rotation/mirror
states, including pin joins, circle geometry and 48 field layouts. Focused
regressions and an independent review passed; the browser/native SVG comparison
was inspected. Browser font metrics remain approximate. These checks do not
establish pixel equivalence for every KiCad symbol or reproduce a private design.

A deterministic CPU fixture with 20,001 minimal single-pad components, 32 copper
layers and a 1200 × 1200 mm outline produced 60,090 primitives. Parsing took
176 ms and geometry preparation 648 ms, with about 463 MiB peak Node process
memory on the development host. This is not a complex BGA assembly, browser
frame-rate measurement, physical-phone test or manufacturing qualification.

A second fixture gives each of the 20,001 components one through-hole pad
spanning all 32 copper layers. Its 1,320,153 primitives passed parsing,
geometry, model construction and connectivity, including the final pad.
Geometry preparation took 3.83 seconds and peak process memory was about
1.19 GiB. This demonstrates why desktop and phone geometry budgets differ.

The shared KiCad WebView source has matching large-source and inspection work
with independent tests. Its existing generated distributions are not updated
by this KiCad Online release; SDK publication remains separate.

Separate core, prepreg and metal-core solids are not available in the current
renderer. Expand fades the represented substrate and does not invent a stackup.
Altium beta remains excluded. Android uses the established development signer;
an unsigned AAB is not a Google Play publication.
