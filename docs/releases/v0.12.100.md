# KiCad Online 0.12.100 / Android 1.98

GitHub preview. Store submissions and existing reviews are unchanged. Altium beta remains separate and excluded.

## Changes

- Harden browser-session issue and discussion creation against duplicate sends when GitHub accepts Create but its readback becomes unavailable. Uncertain outcomes retain their receipt and cannot silently resend after a worker restart.
- Improve private repository discovery and authenticated website reads without adding repository OAuth permissions. Retain exact revision and account checks for review operations.
- Keep comment content prominent: compact thread actions, metadata in options, diagnostics in Settings, direct navigation from anchored comments, and a separate Go to action. Hide internal receipt markers in display while preserving original remote text.
- Display drawing markers and areas for source-linked replies. Normal drawing clicks pass through area overlays; Ctrl/Command-click selects an area. Individual replies can retain separate source locations.
- Improve minimap branch spacing and labels, standardize its controls, and restore the compact minimap after choosing a sheet from its maximized view.
- Default the schematic explorer to Sheets. Show a Root badge and saved sheet-page numbers, with page lookups cached and scoped to the loaded root. Reused files can list several saved instance pages.
- Refine project cards, variable resolution and provenance, BoM selection, text expressions and saved schematic tables. Unsupported or unresolved source constructs remain identifiable rather than being replaced by invented values.
- Use a consistent immediate loading screen during project discovery and drawing preparation. Show real stages, retain cancellation where supported, and respect reduced-motion settings.
- Add manual extension update checks and store links in About and Settings. Clearly identify local development copies; store updates do not replace an unpacked installation. Never force-reload active review work.
- Keep the top-bar help action within its icon button and wrap help content at narrow widths.

## Validation and limits

The existing acceptance in an authorized private test repository verified one issue creation, an extension reply visible on GitHub, and a website reply automatically read back into the viewer with the API review account signed out. This evidence predates the final UI refinements and is not a substitute for their installed-browser acceptance.

The post-Create binding-loss regression covers Issues and Discussions, including a recreated adapter and an unchanged mutation ID; it confirms that only one Create is dispatched. Discussions was unavailable in the private live test repository, so live Discussion creation is not claimed.

The JavaScript gate passed all 2,803 tests. The Python suite ran 166 tests with two environment skips; the Java boundary-policy check subsequently passed with the installed JDK, leaving only the Windows symlink-privilege skip. All 21 package tests passed. The offline Android assemble, lint and bundle tasks passed. Package/source and checksum audits bind the downloads to the exact source recorded in the release manifest.

After reloading the installed extension, the user confirmed both QA replies appeared, clicking an anchored comment navigated to its drawing, Sheets opened by default with Root/page badges, and the Help icon stayed inside the top bar. This final UI acceptance is user-reported: Windows automation could not activate the captured Chrome window. It does not establish every provider, report type, image workflow or popup combination. Firefox Android, native Safari, organization-wide policy compatibility, physical-phone acceptance and full Altium viewer parity are not implied.

Android uses the established development signing identity. Its AAB is unsigned; this is not a Google Play release.
